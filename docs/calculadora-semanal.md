# Solicitud MPNC

En el menú se llama **Solicitud MPNC**. Reemplaza el Excel de solicitud semanal. Las recetas de pesaje de Alibal (`recetas` / `receta_items`) no se tocan: miden otra cosa (kilos de una línea de producción). Esta solicitud tiene tablas propias, `calc_*`.

El pedido se arma una sola vez. **Crear solicitud** abre la semana. El primer paso anota los batches de cada producto, de lunes a viernes, en fichas (no en una tabla ancha). **Siguiente** pasa al material de empaque: una ficha por material, con la cantidad a pedir. **Guardar** pregunta si está seguro. Si no, se sigue editando. Si sí, `calc_planes.cerrado` queda en 1, se muestra la planilla y se puede imprimir. Una solicitud guardada, al abrirla desde la lista, solo muestra esa planilla. Una que sigue en curso vuelve al formulario.

Si la base ya existía, hay que aplicar `supabase/migraciones/2026-11-20-solicitud-cerrada.sql`. En local la columna se agrega sola al abrir la solicitud.

El total de un ingrediente es la suma, sobre las filas del plan, de los batches de lunes a viernes por los kilos de ese ingrediente en la receta de la fila. Varias presentaciones comparten receta, así que sus batches se suman antes de multiplicar.

El empaque no trae cantidad por batch en el Excel (eran totales de un despacho viejo). Queda vacío hasta que se escriba en la receta. Mientras tanto, la cantidad solicitada se anota a mano. `cantidad_observada` es solo referencia y no se multiplica.

El carmín queda en una sola fila, como el Excel: el de MTD Con Todo (0,468 kg/batch, antes anotado como MPCM01182) se suma en **MPCM01004**. En la semana de ejemplo eso da **323,812 kg**. Las únicas diferencias que se mantienen frente al Excel impreso son el benzoato (120,67 kg, no 124,87) y el ajo (MPCM01011 Ajo en polvo, no MPCM01175).

Si la base ya se sembró con MPCM01182, hay que aplicar `supabase/migraciones/2026-11-19-carmin.sql`. Aunque no se aplique, la hoja igual agrupa ese código dentro de MPCM01004.

## SQL para Supabase

Está al final de `supabase/esquema.sql`. Se puede ejecutar de nuevo.

```sql
CREATE TABLE IF NOT EXISTS calc_recetas (
  id TEXT PRIMARY KEY,
  nombre TEXT NOT NULL,
  planta TEXT NOT NULL,
  kg_batch DOUBLE PRECISION,
  fecha_formula TEXT NOT NULL DEFAULT '',
  nota_empaque TEXT NOT NULL DEFAULT ''
);

CREATE TABLE IF NOT EXISTS calc_receta_items (
  id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  receta_id TEXT NOT NULL,
  codigo TEXT NOT NULL,
  nombre TEXT NOT NULL,
  tipo TEXT NOT NULL CHECK (tipo IN ('mpnc', 'empaque')),
  kg_por_batch DOUBLE PRECISION,
  unidad TEXT NOT NULL DEFAULT 'kg',
  cantidad_observada DOUBLE PRECISION,
  nota TEXT NOT NULL DEFAULT '',
  orden INTEGER NOT NULL DEFAULT 0,
  UNIQUE (receta_id, codigo, tipo)
);

CREATE TABLE IF NOT EXISTS calc_plan_filas (
  orden INTEGER PRIMARY KEY,
  planta TEXT NOT NULL,
  nombre TEXT NOT NULL,
  receta_id TEXT NOT NULL
);

CREATE TABLE IF NOT EXISTS calc_catalogo (
  codigo TEXT NOT NULL,
  tipo TEXT NOT NULL CHECK (tipo IN ('mpnc', 'empaque')),
  nombre TEXT NOT NULL,
  unidad TEXT NOT NULL,
  nota TEXT NOT NULL DEFAULT '',
  orden INTEGER NOT NULL,
  PRIMARY KEY (codigo, tipo)
);

CREATE TABLE IF NOT EXISTS calc_planes (
  id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  anio INTEGER NOT NULL,
  semana INTEGER NOT NULL CHECK (semana BETWEEN 1 AND 53),
  creado_en TEXT NOT NULL DEFAULT to_char(clock_timestamp() AT TIME ZONE 'UTC', 'YYYY-MM-DD"T"HH24:MI:SS.MS"Z"'),
  actualizado_en TEXT NOT NULL DEFAULT to_char(clock_timestamp() AT TIME ZONE 'UTC', 'YYYY-MM-DD"T"HH24:MI:SS.MS"Z"'),
  usuario TEXT NOT NULL DEFAULT '',
  cerrado INTEGER NOT NULL DEFAULT 0,
  UNIQUE (anio, semana)
);

CREATE TABLE IF NOT EXISTS calc_plan_batches (
  plan_id INTEGER NOT NULL,
  fila_orden INTEGER NOT NULL,
  lunes DOUBLE PRECISION NOT NULL DEFAULT 0,
  martes DOUBLE PRECISION NOT NULL DEFAULT 0,
  miercoles DOUBLE PRECISION NOT NULL DEFAULT 0,
  jueves DOUBLE PRECISION NOT NULL DEFAULT 0,
  viernes DOUBLE PRECISION NOT NULL DEFAULT 0,
  PRIMARY KEY (plan_id, fila_orden)
);

CREATE TABLE IF NOT EXISTS calc_plan_solicitado (
  plan_id INTEGER NOT NULL,
  codigo TEXT NOT NULL,
  tipo TEXT NOT NULL CHECK (tipo IN ('mpnc', 'empaque')),
  cantidad DOUBLE PRECISION,
  PRIMARY KEY (plan_id, codigo, tipo)
);

CREATE INDEX IF NOT EXISTS idx_calc_items_receta ON calc_receta_items (receta_id, orden);
CREATE INDEX IF NOT EXISTS idx_calc_planes_semana ON calc_planes (anio DESC, semana DESC);

ALTER TABLE calc_recetas ENABLE ROW LEVEL SECURITY;
ALTER TABLE calc_receta_items ENABLE ROW LEVEL SECURITY;
ALTER TABLE calc_plan_filas ENABLE ROW LEVEL SECURITY;
ALTER TABLE calc_catalogo ENABLE ROW LEVEL SECURITY;
ALTER TABLE calc_planes ENABLE ROW LEVEL SECURITY;
ALTER TABLE calc_plan_batches ENABLE ROW LEVEL SECURITY;
ALTER TABLE calc_plan_solicitado ENABLE ROW LEVEL SECURITY;
```

La semilla `data/seed-calculadora.json` se carga sola la primera vez que alguien abre la calculadora y las filas del plan están vacías.
